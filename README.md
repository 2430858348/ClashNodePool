# ClashNodePool

本地跑的 Clash 节点池服务：持续采集公开免费节点、测速筛活，然后通过**带有效期的订阅链接**喂给你的 Clash。

## 快速开始

### 首次安装（在电脑上第一次用）

1. 双击 `start.bat` —— 建虚拟环境、装依赖、启动服务并打开浏览器（约 1–2 分钟）
2. 双击 `create-shortcut.bat` —— **在桌面生成「ClashNodePool」图标**（以后日常就双击它）
3. 在面板里点「立即刷新」跑第一轮采集，节点池才有数据
4. 在「订阅令牌」里复制订阅链接，填进 Clash 的订阅栏

> 桌面图标是一个 `.lnk` 快捷方式，指向本文件夹的 `open-panel.bat`，**每台电脑要各自生成一次**，所以它不放在仓库里（里面的绝对路径换台机器就失效）。`create-shortcut.bat` 就是干这个的，用相对路径自动定位，clone 到任何目录都能用。

### 日常使用

**双击桌面上的「ClashNodePool」图标。**

三条行为：

- 服务没在跑 → 后台无窗口拉起，就绪后自动开面板。**不会留黑框**（启动器窗口两三秒后自己关掉）
- 服务已在跑 → 直接开面板，秒开
- **关掉面板页面 → 服务自动退出**（约 10 秒后），不留后台进程

- 面板地址：`http://127.0.0.1:8787`
- 想让它一直挂着（比如给别的设备用），用 `run-server.bat` 启动即可

## 启动入口与生命周期

| 文件 | 用途 | 关页面会停吗 |
|---|---|---|
| 桌面「ClashNodePool」图标 | 日常双击：拉起服务 + 开面板，无窗口 | 会 |
| `open-panel.bat` | 图标指向的就是它 | 会 |
| `run-server.bat` | 调试用：前台跑，能看到实时报错 | **不会**，关窗口才停 |
| `start.bat` | 首次安装：建环境、装依赖、启动、开浏览器 | 会 |
| `create-shortcut.bat` | 首次安装：在桌面生成上面的图标 | —（不启动服务） |

### 关页面就停是怎么做到的

不是玄学，是心跳：

```
页面每 15 秒 POST /api/beat         → 服务知道「还有人在看」
关闭页面时 sendBeacon /api/bye      → 服务开始 10 秒宽限期
宽限期内又有心跳（比如你按了 F5）   → 撤销，服务继续
宽限期到 / 150 秒没有任何心跳       → 优雅退出，3 秒后强制收尾
```

两个数字是刻意这么定的：宽限 10 秒是为了容错刷新（F5 会先触发 pagehide 再重新加载）；150 秒兜底是因为浏览器会把后台标签页的定时器限流到约每分钟一次，卡太紧会误杀。

## 它是怎么工作的

```
后台每 30 分钟：拉取订阅源 → 解析统一格式 → 去重 → TCP/TLS 测速 → 打标入库 → 淘汰
前台每次拉取：GET /sub/<token> → 校验有效期 → 未过期返回 Clash YAML，过期返回 404
```

## 几个关键设计

**只有探测通过的节点才会下发**
新抓到的节点先记为「不可用」，必须 TCP/TLS 探测通过才进池子。否则第一次采集会把 3000 多条没验证的垃圾节点全塞给你的 Clash。

**过期返回 404，不返回空配置**
Clash 拉取失败只会弹个提示，你现有的节点配置原封不动。如果返回一份 `proxies: []`，Clash 会把你所有节点清空——那才是真正的事故。

**节点池为空时拒绝下发（503）**
同理，宁可让这次更新失败，也不下发空配置。

**TTL 到期直接删行，不是打死亡标记**
否则节点会被永久判死，池子只减不增。删掉之后下一轮采集会把它当新节点重新发现。

**UDP 协议不参与 TCP 探测，但限量放行**
`hysteria2` / `tuic` 走 QUIC（UDP），TCP 探测必然失败。硬测会把好节点全杀掉，所以跳过探测直接放行，但限制在池子容量的 20%（默认 40 条），避免它们挤掉已验证的 TCP 节点。

**连续失败 6 小时后允许复活**
免费节点时好时坏，一次误判不该永久出局。

```

├── start.bat              首次安装：建环境 + 装依赖 + 启动 + 开浏览器
├── create-shortcut.bat    首次安装：一键在桌面生成「ClashNodePool」图标
├── probe.py               端口探测小工具（bat 里调用，避免内联转义问题）
├── icon.ico               桌面图标 + 浏览器标签页图标（同一个文件，6 个尺寸）
├── requirements.txt       依赖
├── config/sources.yaml    节点源（你改这里增删）
├── app/
│   ├── config.py          路径与默认参数
│   ├── db.py              SQLite 数据层 + 轻量迁移
│   ├── parsers.py         订阅解析（YAML / base64 / URI）
│   ├── prober.py          连通性探测
│   ├── pool.py            节点池与淘汰
│   ├── clash.py           Clash 配置生成
│   ├── tokens.py          订阅令牌
│   ├── pipeline.py        采集管道 + 定时调度
│   ├── lifecycle.py       心跳看门狗（关页面即停）
│   └── main.py            FastAPI 服务 + 无窗口守护启动
├── web/index.html         面板
├── .venv/                 虚拟环境（已装好）
└── data/
    ├── nodes.db           自动生成
    ├── server.log         无窗口运行时的标准输出
    └── daemon.log         启动诊断（排查「双击没反应」先看这里）
```

## 调参

改 `config/sources.yaml` 增删节点源，重启生效。

其他参数在 `app/config.py` 的 `DEFAULT_SETTINGS`：

| 参数 | 默认 | 含义 |
|---|---|---|
| `interval_sec` | 1800 | 自动刷新间隔（秒） |
| `probe_concurrency` | 128 | 测速并发数 |
| `probe_timeout` | 4.0 | 单节点测速超时（秒） |
| `max_nodes` | 200 | 池子上限，按延迟取前 N |
| `node_ttl_hours` | 72 | 节点最长存活时间 |
| `fail_streak_kick` | 3 | 连续失败几次踢出 |
| `default_token_ttl_hours` | 168 | 新建订阅默认有效期 |
| `auto_stop_on_page_close` | true | 关页面自动停服务（`run-server.bat` 启动时不生效） |
| `heartbeat_timeout_sec` | 150 | 多久没心跳就兜底停（容忍后台标签页限流） |
| `shutdown_grace_sec` | 10 | 收到关页通知后的宽限秒数（容错 F5 刷新） |

## HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sub/{token}` | Clash 订阅（核心） |
| POST | `/api/beat` | 页面心跳（面板自动调用） |
| POST | `/api/bye` | 页面关闭通知（sendBeacon） |
| GET | `/api/status` | 总体状态 |
| GET | `/api/nodes` | 节点列表 |
| POST | `/api/refresh` | 手动触发一轮刷新 |
| GET/POST | `/api/tokens` | 列出 / 签发订阅 |
| PATCH/DELETE | `/api/tokens/{token}` | 续期、吊销、删除 |
| GET | `/api/sources` | 源健康度 |
| PATCH | `/api/sources/{id}` | 启用 / 关闭源 |
| GET | `/api/logs` | 运行日志 |

## 已知限制

1. **测速只到 TCP/TLS 层**。能筛掉服务器死了、端口关了、IP 被封的，但筛不出「端口通但凭据错了」的节点。真实验证需要外挂 mihomo / sing-box 内核通过代理发请求，属于第二阶段。
2. **不保证有节点可用**。免费源的可用性取决于对方维护状态，工具做的是「把现有资源筛干净」，不是「凭空造节点」。
3. 只监听 `127.0.0.1`，手机等外部设备无法直接访问。

## 合规

境内私自搭建、经营跨境代理有法律边界。本工具定位是**纯本地自用**。不要公开分享订阅链接——既会让节点 IP 迅速被封，也会把你的风险从「个人使用」变成「提供传播」。
